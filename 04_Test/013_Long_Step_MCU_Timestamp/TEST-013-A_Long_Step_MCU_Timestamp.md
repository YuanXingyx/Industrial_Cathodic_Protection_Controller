# TEST-013-A Long Step with MCU Timestamp

## Objective

Improve time-measurement reliability and extend the high-target plateau without changing the validated PI controller baseline.

## Hardware Setup

- MCU: STM32F103C8T6
- ADC feedback: ADC1_IN0 / PA0
- PWM output: TIM3_CH1 / PA6
- UART: USART1 / 115200 / 8N1
- RC plant: 10 kOhm + 1 uF

## Firmware Baseline

- Kp: 0.010 (unchanged)
- Ki: 0.002 (unchanged)
- Base duty: 50%
- Control period and integration dt: approximately 100 ms / 0.1 s
- ADC acquisition: average of up to eight valid conversions per control update
- Integral clamp: -5000 to +5000
- Output clamp: 0% to 100%

No controller tuning, anti-windup change, or hardware change is part of this test.

## MCU Timestamp Telemetry

Every valid telemetry record begins with `TICK=<HAL_GetTick()>`, in milliseconds:

```text
TICK=...,ADC=...,TARGET=...,INT=...,ERR=...,KP=0.010,KI=0.002,OUT=...,DUTY=...
```

The host CSV stores both its original `time_s` and the MCU value as `mcu_tick_ms`. The offline analyzer prefers MCU time when the column exists and falls back to host time for older CSV files.

The uint32 tick can roll over after approximately 49.7 days. The analyzer includes simple rollover unwrapping, although this short test is not expected to reach rollover.

## Long Step Profile

```text
0-10 s:    TARGET=2048
10-90 s:   TARGET=2400
After 90 s: TARGET=2048
```

## Test Procedure

1. Build and flash the prepared Day 10 firmware.
2. Start `serial_plot.py` and capture approximately 160 seconds of telemetry.
3. Confirm every parsed record contains an increasing MCU tick.
4. Preserve the capture as `05_Data/ADC/Day10_Long_Step_Baseline.csv` without overwriting Day 8 evidence.
5. Preserve the response plot as `05_Data/Control_Response/Day10_Long_Step_Baseline.png`.
6. Run `analyze_step_response.py` on the new CSV and confirm it reports `Time source: MCU TICK`.
7. Compare host `time_s` intervals with MCU tick intervals.
8. Evaluate whether the extended TARGET=2400 plateau reaches the existing settling criterion and inspect ADC, ERR, INT, and OUT behavior.

## Expected Observations

- MCU tick should increase monotonically across the capture.
- Target changes should be detected from telemetry near the programmed 10 s and 90 s boundaries.
- The longer 2400 plateau should provide enough observation time to determine whether the response settles under the existing project criterion.
- Integral and output telemetry should show whether slow response coincides with continued integral accumulation or output saturation.

These are expectations, not measured results.
